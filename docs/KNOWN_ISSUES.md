# 已知问题与局限

这里集中记录当前**已确认、且在现有设计下无法根治或刻意接受**的问题。已修复的历史问题不在此列，
见 [GitHub Releases](https://github.com/os233/WaterReminder/releases) 各版本的更新说明。

## 提醒不响？先按这个顺序排查

「提醒不响」绝大多数是 ROM 省电策略所致：

1. 通知权限（Android 13+）与精确闹钟权限（Android 12+ 系统设置里的「闹钟和提醒」）是否授予；
2. OPPO 系（OPPO / realme / 一加）是否打开「应用耗电管理 → 允许完全后台行为」与「自启动」两项；
3. 应用是否被系统 force-stop（一键清理、智能省电）：force-stop 后处于 stopped 状态，任何广播
   都唤不醒它，只能重新打开应用恢复（诊断命令见 README「后台提醒与 ROM 行为」）；
4. 免打扰时段是否覆盖了当前时间。

抓诊断日志：`adb logcat -s WaterReminder` —— 闹钟触发、补排、免打扰跳过、更新下载与校验的
关键分支都会打到这里，报障时附上这段输出即可定位。

## OPPO 系 ROM 后台冻结闹钟（无法根治）

- **现状**：2026-09-21 在 realme RMX3800 / realme UI 16 上实测，未加白名单时后台应用的精确闹钟
  会被整体搬到 3 天后（`dumpsys alarm` 里 `whenElapsed` 被改写），换任何闹钟 API 都一样。
- **缓解**：应用内常驻显示「允许完全后台行为 + 自启动」引导，实测打开后延后立刻消失。
  白名单状态无法探测，所以引导不会按「看起来已放行」隐藏。
- **为什么无法根治**：厂商 ROM 行为，没有公开开关；常驻前台服务保活已被实测证明无效
  （进程活着反而被 ROM 冻结，冻结后投递被丢弃），故不引入。

## force-stop 后提醒静默失效

- **现状**：系统 force-stop 应用时会连同 PendingIntent 清掉所有闹钟，且 stopped 状态收不到
  任何广播（含 `BOOT_COMPLETED`）；而 prefs 里的提醒开关仍是「开启」，界面看着正常。
- **缓解**：每次启动、开机与覆盖安装时按 prefs 记的原定时刻幂等补排（`restoreAlarmIfNeeded`），
  不会把提醒往后推。
- **边界**：两次打开应用之间到期的提醒无法补 —— 平台行为，应用侧无解。

## 更新链路（下载 → 校验 → 安装）没有自动化测试

- **现状**：JVM 单元测试只覆盖版本清单解析与 SHA-256 算法本身；DownloadManager 交互、
  FileProvider 路径、安装器行为都依赖真机。
- **缓解**：每个版本发布前在设备上手工走一遍完整链路。设备上 `update_prefs.xml` 出现
  `last_check_at` 只能证明检查请求成功，不证明版本比较、下载与摘要校验正确。

## 版本号重置造成的升级断层（已接受的兼容影响）

- **现状**：2026-09-15 版本号从 1.4.0（versionCode 7）重置为 0.0.1。旧包用户装不上任何
  重置后的版本（Android 拒绝降级安装），应用内更新也不会给他们提示。
- **处置**：影响已被接受（详见 AGENTS.md 第 5 节）；旧版本用户需卸载重装最新包。

## lint 只报告、不拦截

- **现状**：CI 里 `lintDebug` 带 `continue-on-error: true`，lint 问题不会挡住构建。
- **原因**：现阶段避免 lint 噪音阻塞发布；修复随手跟进，之后若需要门禁会重新评估。
